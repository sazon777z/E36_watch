# BMW E36 On-Board Computer & Cockpit Gauge (ESP32-S3 + GMT024-08 ST7789)

Проект цифровых часов, бортового компьютера и спортивного кругового прибора в штатное место центральной консоли BMW E36 (1991). Построен на базе **ESP32-S3** и графической библиотеки **LVGL 8.3**, с прямой интеграцией по CAN-шине с ЭБУ **MegaSquirt 2**, GPS-модулем **u-blox NEO-7M**, настраиваемой системой аварийных предупреждений (варнингов) и обновлением прошивки по Bluetooth.

---

## 1. Аппаратная часть (Распиновка подключения)

### Дисплей GMT024-08 (ST7789 SPI TFT 2.4" 240x320) к ESP32-S3:

| Пин дисплея | Пин ESP32-S3 | Назначение |
|---|---|---|
| **VCC** | 3.3V | Питание дисплея |
| **GND** | GND | Земля |
| **SCL** | **GPIO 13** | SPI Clock (SCK) |
| **SDA** | **GPIO 12** | SPI Data / MOSI |
| **RES / RST** | **GPIO 11** | Сброс дисплея |
| **DC** | **GPIO 10** | Выбор Режим/Команда |
| **CS** | **GPIO 9** | Chip Select |
| **BLK / BL** | **GPIO 8** | Подсветка (вкл/выкл, всегда 100% яркость, регулировки нет) |

### CAN-трансивер WCMCU-230 (SN65HVD230) к MegaSquirt 2:

| Пин трансивера | Пин ESP32-S3 / Авто | Описание |
|---|---|---|
| **3V3** | **3.3V** | Питание логики трансивера от шины 3.3V |
| **GND** | **GND** | Общий провод (земля) |
| **CTX** | **GPIO 6** | Вход данных CAN (TWAI TX) |
| **CRX** | **GPIO 7** | Выход данных CAN (TWAI RX) |
| **CANH** | К проводу **CAN_H** | Шина данных к блоку MegaSquirt 2 |
| **CANL** | К проводу **CAN_L** | Шина данных к блоку MegaSquirt 2 |

> [!IMPORTANT]
> Линии данных подключаются **напрямую**, а не крест-накрест (**CTX -> GPIO 6**, **CRX -> GPIO 7**).

### GPS-модуль u-blox NEO-7M к ESP32-S3:

| Пин NEO-7M | Пин ESP32-S3 | Описание |
|---|---|---|
| **VCC** | **3.3V** или **5V** | Питание модуля |
| **GND** | **GND** | Общая земля |
| **TX** | **GPIO 44 (RX)** | Выход NMEA данных GPS в ESP32 |
| **RX** | **GPIO 43 (TX)** | Вход команд GPS из ESP32 |

### Дополнительные подключения:
* **GPIO 14:** Физическая кнопка переключения (клик - смена экрана; двойной клик - переключение датчика прибора; удержание - сброс суточного одометра).
* **GPIO 0:** Встроенная кнопка BOOT на плате ESP32-S3 (дублирует внешнюю кнопку для стендовых тестов).

## 2. Настройка в программе TunerStudio (MegaSquirt 2)

Чтобы ЭБУ отдавал данные в приборную панель по CAN-шине:
1. Откройте проект в **TunerStudio MS**.
2. Перейдите в меню **CAN-bus / Testmodes -> CAN Parameters**:
   - **Master Enable:** установите в **Enable (On)**.
3. Перейдите в меню **CAN-bus / Testmodes -> Dash Broadcasting** (или *CAN Realtime Data Broadcasting*):
   - **Enable:** установите в **On**.
   - **Baud Rate:** **500k** (500 kbit/s).
   - **Configuration:** **Automatic** (базовый ID 1512/1520).
4. Нажмите кнопку **Burn** для сохранения в память ЭБУ.

## 3. Инструкция по сборке в Arduino IDE

### Шаг 0: Секреты (secrets.h)
PIN Bluetooth (`BLE_PASSKEY`), код обновления (`OTA_PIN`) и ключи радиоканала TunerStudio (`TS_LINK_PMK`, `TS_LINK_LMK`) хранятся в `secrets.h`. Этот файл внесён в `.gitignore` и в репозиторий не попадает. Без него сборка остановится с подсказкой.

Скопируйте `secrets.example.h` → `secrets.h` и впишите свои значения. Для донгла то же самое: `extras/ts_dongle_c3/secrets.example.h` → `extras/ts_dongle_c3/secrets.h`, с теми же ключами `TS_LINK_*`, что у дэшборда.

### Шаг 1: Установка библиотек
В Arduino IDE перейдите в меню **Скетч -> Подключить библиотеку -> Управлять библиотеками...** и установите:
1. **`lvgl`** (версия **8.3.11** от LVGL)
2. **`Adafruit GFX Library`** (от Adafruit)
3. **`Adafruit ST7789 and ST7735 Library`** (от Adafruit)
*(При предложении установить зависимые библиотеки нажмите "Install All")*

Скопируйте `extras/lv_conf.h` в папку библиотек (`Документы\Arduino\libraries\lv_conf.h`, рядом с папкой `lvgl`). Важно: в нем включен `LV_SPRINTF_USE_FLOAT 1` — без этого вместо дробных чисел на экране будет буква `f`. С версии 2.8.1 в нем же `LV_MEM_CUSTOM 1`: память LVGL берется из PSRAM. Старый `lv_conf.h` с пулом 80 кБ во внутренней RAM не оставляет памяти Wi-Fi, и мост TunerStudio не работает (статус `NOMEM`).

### Шаг 2: Настройки платы в Arduino IDE
В меню **Инструменты (Tools)** выберите:
- **Плата (Board):** `ESP32S3 Dev Module`
- **USB CDC On Boot:** `Enabled`
- **Flash Size:** `4MB` (или `8MB`/`16MB`)
- **Partition Scheme:** `Minimal SPIFFS (1.9MB APP with OTA/190KB SPIFFS)` — с мостом TunerStudio (Wi-Fi/ESP-NOW) прошивка ~1.6 МБ и в `Default 4MB` (1.25 МБ) не помещается. NVS (пробег, настройки) остаётся на прежнем месте. **Первый раз после смены схемы прошивайте по USB**: по Bluetooth новая таблица разделов не записывается.
- **PSRAM:** `QSPI PSRAM` — на плате встроенная PSRAM 2 МБ (ESP32-S3 с R2), в ней живет память LVGL. Без PSRAM LVGL возьмет внутреннюю RAM, и на мост TunerStudio ее не хватит.
- arduino-cli: `esp32:esp32:esp32s3:CDCOnBoot=cdc,USBMode=hwcdc,PartitionScheme=min_spiffs,FlashSize=4M,PSRAM=enabled`

### Шаг 3: Загрузка
Откройте файл `E36_watch.ino` и нажмите кнопку **Загрузка (Upload)**.

## 4. Экраны (UI)

Общая строка статуса сверху (индикатор связи MS2, название экрана, спутники GPS) и точки-индикатор страниц снизу. Экраны переключаются кликом кнопки с анимацией сдвига; значения плавно подтягиваются к новым (без скачков), обновление до 60 кадров/с.

1. **Часы:** крупные часы с мигающим двоеточием, плитки `BOOST`, `WATER`, `AFR` с мини-шкалами. При тревоге плитка мигает красным.
2. **Трип:** GPS-скорость, мгновенный расход (L/H на месте, L/100 в движении), пробег поездки (сброс удержанием кнопки), средний расход, израсходованное топливо.
3. **Мотор:** напряжение АКБ, ОЖ и впуск, AFR и целевой AFR, дроссель и MAP, шкала наддува с меткой 0.
4. **///M:** шифт-лайт из 16 сегментов (мигает красным на отсечке), обороты, наддув, УОЗ.
5. **Прибор:** дуга 270° с крупным значением; 7 датчиков (двойной клик или удержание — следующий), выбор сохраняется во Flash.
6. **Система:** CAN, GPS, Bluetooth OTA, версия и время работы.

## 5. Bluetooth (только обновление прошивки)

Мобильного приложения нет: экран работает как самостоятельный дашборд. Bluetooth (`BMW-E36-OBC`) используется только для обновления прошивки через страницу `ota.html`.

### Сопряжение:
По умолчанию (`BLE_PAIRING_ENABLED 1`) запись зашифрована, при первом подключении запрашивается PIN `BLE_PASSKEY` из `secrets.h`. Не добавляйте плату вручную в «Параметры Bluetooth» Windows: Windows будет держать соединение, и браузер не найдет плату. Если браузер не умеет сопрягаться — `BLE_PAIRING_ENABLED 0`.

### Обновление прошивки по Bluetooth (BLE OTA):
1. Задайте `OTA_PIN` в `secrets.h` и один раз прошейте плату по USB.
2. Схема разделов должна содержать два OTA-слота (`Minimal SPIFFS` — по 1.9 МБ на слот).
3. Arduino IDE: **Скетч → Экспорт бинарного файла**, файл `E36_watch.ino.bin` (не `.merged.bin`).
4. Разбудите плату (кнопка), откройте `ota.html` в Chrome/Edge, нажмите «Подключиться» (если не находит — «Показать все устройства»), выберите `.bin`, введите PIN, «Залить прошивку» (~1–3 мин).
5. Устройство проверит CRC32 и SHA-256 образа и перезагрузится. Автоматического отката нет (загрузчик Arduino ESP32 собран без APP_ROLLBACK): прошивку, падающую при старте, придется перешивать по USB.

Протокол: сервис `c0de0001-…`, CTRL `c0de0002-…` (`begin <size> <crc32hex> <pin>`, `end`, `abort`, `ver`; ответы notify), DATA `c0de0003-…`.

### Постоянное питание и сон:
Плату можно питать постоянно (через преобразователь с малым током покоя). Через 3 минуты тишины на CAN-шине (зажигание выключено, Bluetooth не подключен) пробег сохраняется, экран гаснет, ESP32 уходит в глубокий сон. Просыпается по первому сообщению MegaSquirt на CAN или по кнопке GPIO 14. Время во сне идет и уточняется по GPS. GPS NEO-7M на постоянном питании потребляет ~35 мА (~0.85 А·ч в сутки).

## 6. Беспроводное подключение TunerStudio (мост к ЭБУ)

```
TunerStudio ─COM─ донгл ESP32-C3 (USB ноутбука) ~ESP-NOW~ дэшборд S3 ─USB─ FT232 ЭБУ ─ MegaSquirt 2
```

* Донгл: `extras/ts_dongle_c3/ts_dongle_c3.ino` (плата **ESP32C3 Dev Module**, USB CDC On Boot: **Enabled**). В Windows это постоянный COM-порт: TunerStudio сам восстанавливает связь через 1–2 с после включения зажигания.
* Дэшборд: `ts_bridge.cpp` + `ts_link.h`. Плата работает **USB-хостом** для FT232RL на плате ЭБУ. Пока MegaSquirt на связи по CAN, подаётся питание на FT232 (`PIN_USB_VBUS_EN`). Перед сном питание снимается.
* `ts_link.h` одинаковый во всех прошивках (дэшборд, донгл, диагностика). Канал и номер пары (`TS_LINK_CHANNEL`, `TS_LINK_NET_ID` в `config.h`) должны совпадать с `LINK_CHANNEL`, `LINK_NET_ID` в донгле. Ключи `TS_LINK_PMK` / `TS_LINK_LMK` (ровно 16 символов) должны совпадать в `secrets.h` обеих прошивок. После смены ключей перепрошейте оба устройства.
* Настройки Arduino для дэшборда остаются прежними: **USB CDC On Boot: Enabled**, USB Mode: Hardware CDC and JTAG. CDC On Boot нельзя выключать: тогда `Serial` займёт GPIO 43/44 вместе с GPS.
* После запуска моста USB платы занят хостом, и монитор порта не работает. **Сервисный режим:** держите кнопку GPIO 14 при подаче питания (не при пробуждении) ~1,5 с. USB-хост не запустится, USB работает как раньше (монитор порта, прошивка). Радио при этом работает, и раз в 2 с в порт печатается его состояние: так проверяется связь с донглом на столе.
* Прошивка дэшборда — по Bluetooth (`ota.html`), по USB в сервисном режиме или в режиме загрузчика: держите BOOT, нажмите RESET.
* Экран «Система», строка `BLE / TS`:
  * `TS WAIT` — нет ни ЭБУ, ни ноутбука;
  * `ECU` — FT232 подключён;
  * `PC` — донгл на связи;
  * `LINK` — всё готово;
  * `SRV ...` — сервисный режим (без USB-хоста);
  * `NOMEM` — не хватило внутренней RAM (проверьте PSRAM и `lv_conf.h`);
  * `ERR WIFI` / `ERR USB` — ошибка запуска радио / USB-хоста;
  * `OFF` — мост выключен в `config.h`.
  * Пока FT232 не открыт, после статуса видно, что видит USB-хост (с версии 2.8.3), например `TS PC c1 d1 f1 n1 e0`:
    * `c0` — на линиях D+/D− никого нет: нет питания FT232, переходник, кабель или USB-C вставлен «не той» стороной; `c1` — устройство подключено;
    * `d<n>` — сколько устройств у стека USB, включая то, которое опознаётся прямо сейчас;
    * `f<n>` — сколько раз опознание дошло до дескриптора устройства (`c1 d1 f0` — устройство подключено, но не отвечает: помехи, длинный или плохой кабель);
    * `n<n>` — сколько событий «новое устройство» получил мост (`f1 n0` — опознание не завершилось). Мост и сам раз в секунду проверяет список устройств;
    * `e<n>` — на каком шаге не открылся FT232: 1 — открытие, 2 — дескрипторы, 3 — устройство не FTDI, 4 — нет конечных точек, 5 — захват интерфейса, 6 — память, 7 — настройка FT232, 8 — запуск приема.
* Рядом с версией на экране «Система» показана свободная внутренняя RAM. Для работы моста нужно не меньше ~16 кБ (`TS_MIN_FREE_INTERNAL`).
* **Диагностика донгла:** `extras/ts_dongle_diag` прошивается в донгл вместо обычной прошивки и раз в секунду печатает в его COM-порт, что он слышит от дэшборда: принятые кадры, уровень сигнала, MAC соседа, `up` (связь) и `ecu` (FT232 готов). `secrets.h` для неё — копия из `extras/ts_dongle_c3`. TunerStudio с ней не работает: после проверки верните обычную прошивку.

### Ключ питания FT232 (VBUS)

FT232 на плате ЭБУ питается от USB. Если держать на нём 5 В постоянно, он через линию TX подпитывает выключенный ЭБУ. Поэтому 5 В подаются только по команде с GPIO 5:

```
 +5V дэшборда ──┬───────── S  Q1 (P-MOSFET AO3401 / Si2301)
               R1 10к       G ──┐
                └───────────────┤
                                └── C  Q2 (NPN BC547 / S8050)
 GPIO 5 ── R2 1к ── B Q2;   R3 10к: B–GND;   E Q2 ── GND
 D Q1 ──┬── красный провод VBUS к ЭБУ
       C1 22 мкФ
        └── GND
```

**Кабель:** USB-C дэшборда → OTG-переходник USB-C/USB-A → кабель к ЭБУ.
* D+ (зелёный), D− (белый), GND (чёрный) и экран идут насквозь.
* Красный провод на стороне ЭБУ подключается к стоку Q1. Красный провод со стороны дэшборда изолируйте.

Если плата дэшборда сейчас питается **через USB-C**, переведите питание на вывод 5V/VIN: USB-C теперь нужен для кабеля к ЭБУ.

### Команды через USB (монитор порта 115200):
| Команда | Действие |
|---|---|
| `n` / `1`–`6` | следующий экран / экран по номеру |
| `g` | следующий датчик прибора |
| `h` / `r` | удержание кнопки / сброс трипа |
| `z5`, `z-3` | часовой пояс UTC+5, UTC-3 |
| `d` | демо-режим: имитация данных MegaSquirt (для проверки экрана на столе) |
| `c` | снимок экрана (бинарный поток RGB565 между `CAPSTART` и `CAPEND`) |
| `p` | состояние GPS и фильтра стоянки |
| `t` | тест цветов дисплея |
| `s` / `q` | глубокий сон / перезагрузка |
